Pīkau

Personal Project | Native Android

Pīkau is a native Android app for planning tramping trips and managing gear. The name is te reo Māori for a pack carried on the back. I am building it as a production-shaped codebase: modular Gradle, Jetpack Compose, Hilt, Room, and Navigation 3. Home, Gear, Trips, and Me are in the app. Trip and gear detail, create flows, and the remaining Me destinations are still to build.

01/ The Challenge

Trip planning on the trail still splits across paper, notes apps, and tools that need a signal. I wanted a single offline-first companion that matches how I actually pack and walk in Aotearoa, built to the same standard as a commercial Android app: isolated features, a real persistence layer, shared UI, and tests, rather than a single-module prototype.

02/ Architecture

Features depend on repositories, not on each other. The app module owns navigation. Shared Android setup lives in convention plugins so each module stays small.

Modular Gradle

The app is split into Gradle modules so home, trips, gear, and profile stay independent. The app module is only the shell: it applies Hilt and owns navigation. Each feature owns its screens. Shared UI, repositories, Room, models, and test helpers live in core.

Schema before screens

A trip has a name, location, dates, categories, and difficulty. Gear has a name, category, weight in grams, and suggested trip types. Categories are seeded on first launch. Packing list items, food items, and trip notes are in the same schema.

Navigation 3

Four tabs sit in a pager, and each tab keeps its own history. Tapping a trip or a gear item is meant to open a full screen and hide the tab bar. That screen is designed, not built yet.

Shared Compose UI

Theme, type, buttons, chips, inputs, list rows, and loading and error states live in core/ui. Screens collect a UiState from Hilt ViewModels: loading, content, or a full-screen error with retry.

03/ Design

A four-tab companion for the pack: home at a glance, a gear library, trip lists, and a profile, with packing, food, and notes kept on device.

04/ Quality

The current value of the project is a maintainable Android structure with coverage on the layers that already exist, not a finished packing product.

Tests on the logic

ViewModels are tested with Turbine. Room repositories have their own tests, with fixtures for entities and fakes. Compose UI tests cover the shared button, chip, and tabs components.

CI on main

GitHub Actions runs ./gradlew build and ./gradlew test on Ubuntu with JDK 17 for every push and pull request to main.

Screenshot tests, local only

Roborazzi goldens live under core/ui. They are not compared on CI because they were recorded on macOS and Ubuntu renders edges differently. Record and verify stay on one machine.

05/ Next

You can already browse Home, Gear, Trips, and Me. The next screens are the ones that open from those lists.

Trip and gear detail

Tapping a trip or a gear item hides the tab bar, but the screen that should open is not built yet. For a trip, that screen is the overview, packing list, food, and notes.

Adding a trip or gear item

Lists work. There is not yet a form to create a trip or a piece of gear. Those forms will use the fields already stored on the device.

Profile settings

The Me tab already shows settings, notifications, emergency contact, privacy, and support. Tapping those rows does not open a screen yet.
